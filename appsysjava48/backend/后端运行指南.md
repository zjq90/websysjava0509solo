# 后端项目运行指南

## 🔧 已修复的问题

### 1. Swagger 启动失败（最常见！）
**错误信息**：
```
Failed to start bean 'documentationPluginsBootstrapper'
nested exception is java.lang.NullPointerException
```

**问题原因**：
Spring Boot 2.6+ 版本默认使用 `PathPatternParser` 进行路径匹配，但 SpringFox 3.0.0 仍使用旧的 `AntPathMatcher`，导致兼容性问题。

**已修复**：
在 `application.yml` 中添加：
```yaml
spring:
  mvc:
    pathmatch:
      matching-strategy: ant_path_matcher
```

## 🚀 启动步骤

### 前置要求
- JDK 11+
- Maven 3.6+（或使用 IDE 内置 Maven）
- **可选**：Redis（不启动也能运行，只是缓存功能不可用）

### 方式 1：IDE 启动（推荐）
1. 使用 IntelliJ IDEA 或 Eclipse 打开 `backend` 目录
2. 找到主类：`src/main/java/com/psyconsult/PsyConsultApplication.java`
3. 右键点击 → Run 'PsyConsultApplication'
4. 等待启动完成（看到 `Started PsyConsultApplication in X.XXX seconds` 即成功）

### 方式 2：Maven 命令启动
```bash
cd backend
mvn spring-boot:run
```

### 方式 3：打包后运行
```bash
cd backend
mvn clean package
java -jar target/psyconsult-backend-1.0.0.jar
```

## ❌ 常见问题及解决

### 问题 1：Redis 连接失败
```
Unable to connect to Redis
```

**解决方法**：
- **方案 A**：启动本地 Redis（默认端口 6379）
- **方案 B**：不启动 Redis，项目仍能运行（只是缓存功能不生效）
- **方案 C**：修改 `application.yml` 禁用 Redis：
  ```yaml
  spring:
    autoconfigure:
      exclude:
        - org.springframework.boot.autoconfigure.data.redis.RedisAutoConfiguration
  ```

### 问题 2：端口 8080 被占用
```
Port 8080 was already in use
```

**解决方法**：
修改 `application.yml` 中的端口：
```yaml
server:
  port: 8081  # 或其他可用端口
```

### 问题 3：Swagger 页面 404
**解决方法**：
1. 确保启动时没有 Swagger 相关报错
2. 访问正确地址：`http://localhost:8080/swagger-ui/`（注意末尾的斜杠）
3. 如果仍不行，尝试清理项目后重新编译

### 问题 4：H2 控制台无法访问
**解决方法**：
1. 确认 `application.yml` 中开启了 H2 控制台：
   ```yaml
   spring:
     h2:
       console:
         enabled: true
   ```
2. 访问地址：`http://localhost:8080/h2-console`
3. JDBC URL 必须填写：`jdbc:h2:mem:psyconsult_db`

## 🧪 API 测试

启动成功后，可以通过 Swagger 测试以下 API：

### 咨询师相关
- `GET /api/counselor` - 获取所有咨询师
- `GET /api/counselor/senior` - 获取资深咨询师（督导）

### 日程管理
- `GET /api/schedule/counselor/{id}/date/{date}` - 获取指定日期排班
- `POST /api/schedule` - 创建排班
- `GET /api/schedule/counselor/{id}/available/{date}` - 获取可用时段

### 预约管理
- `GET /api/appointment/counselor/{id}` - 获取咨询师预约
- `POST /api/appointment` - 创建预约
- `PUT /api/appointment/{id}/status?status=confirmed` - 更新预约状态

### 咨询记录
- `GET /api/record/counselor/{id}` - 获取咨询师的咨询记录
- `POST /api/record` - 创建记录（**自动检测敏感词并触发预警**）
- `PUT /api/record/{id}` - 更新记录

### 危机预警
- `GET /api/crisis` - 获取所有预警
- `GET /api/crisis/status/{status}` - 按状态获取预警
- `PUT /api/crisis/{id}/handle?result=已处理` - 处理预警

## 🚨 敏感词检测机制

系统内置危机敏感词检测功能，当创建咨询记录时，内容包含以下关键词会**自动触发危机预警**：

```
自杀、想死、不想活、结束生命、活不下去、
自残、自伤、自杀倾向、自我伤害、
跳楼、割腕、喝农药、上吊、烧炭
```

触发后会自动创建一条状态为 `pending` 的危机预警记录，并通知相关督导。

## 📝 开发建议

1. **开发时**：可以不启动 Redis，不影响核心功能
2. **测试时**：使用 H2 内存数据库，数据重启后重置
3. **生产时**：建议改用 MySQL/PostgreSQL，配置持久化 Redis
